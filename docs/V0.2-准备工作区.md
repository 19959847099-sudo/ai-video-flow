# V0.2 准备工作区：规则与数据约定

正式产品依据仍为 `重要文档` 中的项目定义 V0.2、项目路线 V0.2、协作规则 V0.1。本文件只说明本轮具体实现，不改变冻结定义。

## 当前闭环

规范剧本 → Parser → 资产需求 → 本地素材扫描 → 缺失 / 歧义 / 变更 → 导入或明确绑定 → 章节 Ready。

Production / Candidate / Review 已接入当前 Shot：缺失需求可通过本地图像 Fixture 或媒体导入形成 Candidate，经 Green / Yellow / Red 判断后另行绑定 Current。Ready 表示本章必需参照已映射到有效本地媒体，且编辑区与已应用剧本一致；不表示审美通过、模型可用或成片完成。轻剪和输出尚未接入。

## 五分钟语法

```text
影片名/名称
01/章节/章节标题

001/镜头标题
【林夏/-/雨衣】/低声
店员/老年/围裙/-
【便利店/雨夜】/雨声、冰柜低鸣

镜头：
【门内后退跟拍】 保持中景，结尾慢慢停住。

动作：
林夏推门进入，右手拿着【红伞.破损】。

表演：
疲惫但克制。

对白：
林夏：雨还要下多久？

连续性：
承接上一镜，雨衣肩部潮湿。
```

- 影片行在开头，一份文档对应一个影片。章节使用 `01/集数`、`01/章节` 或 `01/章节/标题`。章内镜头编号为三位及以上数字，例如 `001/进入`。
- 章节编号全片唯一，镜头编号章内唯一；编号按数值归一，`001` 与 `0001` 不会成为两个镜头。
- 人物行固定四个位置，可连续多行。随后写至多一行环境，再进入自然语言区。支持明确的 `人物：`、`环境：` 前缀。
- `-` 不能用空字符串替代。人物本身不能为 `-`；无人镜头直接省略人物行。
- `【】` 内部的 `/` 不是外部字段分隔符。完整角色只括前三项，音声在外面。
- 普通人物拆成基础人物、人物的年龄状态、人物的服装需求；年龄与服装名在人物范围内识别，避免不同角色误用同名服装。完整角色引用不再强迫准备这些拆分资产。
- Voice 独立按 `人物/音声状态` 识别；音声 `-` 不创建 Voice 需求，环境背景音仍保留。
- 普通环境是自然语言描述，不强制要求背景文件。`【环境名】` 才创建环境参照需求。
- `镜头：` 区的 `【】` 是视频参照；其他自然语言区的 `【】` 是关键物件。资产完整字符串保持独立，`.pro` 等不做推测。
- 动作、镜头、表演、对白、连续性、备注保留文本，不把对白再次拆成强制表单。正文需要 `/` 时先声明对应自然语言区，避免与结构行混淆。
- `//` 开头可写说明。不支持任意 Markdown 表格或 AI 猜格式；错误会显示行号。

## 使用

编辑后约 700 毫秒自动保存草稿；Ctrl+S 立即保存。Ctrl+Enter 或顶部按钮解析并更新需求。

有错误的草稿也会保存，但不会覆盖上一次有效剧本、资产绑定及历史。未应用修改期间，资产确认操作暂停，Ready 失效。点击错误定位原文，修正后再次解析即可。

顶部切换章节，底部 Shot Index 切换镜头；左侧媒体参照台紧邻当前镜头资产需求，右侧阅读或编辑 Production Script。“整章参照”汇总并去重。缺失需求可直接进入生产与判断；已有普通素材的明确映射入口仍保留。资产条目可定位声明行、预览图像或播放音视频。

默认启动恢复上次项目；指定 `--data-dir` 时只打开该路径。章节、镜头和编辑光标位置随项目保存。同一项目只允许一个应用窗口写入。

## 文件夹与匹配

工作区与旧 `data` 独立。默认新项目为 `workspace-v02`，示例为 `example-preparation`。

```text
project.json                  一份原子提交的当前状态
library/
  character/店员.png
  age/店员/老年.png
  costume/店员/围裙.png
  character_visual/林夏/-/雨衣.png
  environment/便利店/雨夜.png
  prop/红伞.破损.png
  voice/林夏/低声.wav
  video_reference/门内后退跟拍.mp4
.history/media/               按内容哈希保留的历史媒体快照
```

文件夹的类型决定资产类别，类型目录下相对路径（去掉最后的扩展名）是自动匹配名。例如 `environment/便利店/雨夜.png` 对应环境 `便利店/雨夜`。

自动匹配只使用相同类型与完整名称，绝不靠相似文件名、创建时间或“最新文件”猜测。唯一有效匹配可直接恢复；同名不同扩展名等多候选进入 unresolved。人工明确绑定后，其他同名文件不会覆盖该选择。

不想组织文件名时，直接从需求卡片导入；系统生成文件名并记录逻辑名与绑定。导入不覆盖已有文件，原始外部文件之后可以移走。

支持图片 PNG/JPEG/WebP/BMP、音频 WAV/MP3/M4A/FLAC/OGG、视频 MP4/MOV/WebM/MKV。图片用 Pillow 校验，音视频调用既有媒体探测；未变化媒体复用校验结果。扩展名对但内容损坏的文件不能让章节 Ready。

本轮 Voice 以参考音频映射；Provider Voice ID 的创建/绑定在后续音声生产轮接入，不伪造已具备的 Provider 能力。

## 外部新增、替换与改名

打开项目时自动扫描；外部操作后点“同步素材库”。状态是上次扫描结果，不声称实时监控文件系统。

| 文件变化 | 系统行为 |
|---|---|
| 新增文件 | 按类型与名称发现，匹配或等待选择 |
| 唯一的旧文件消失、新文件出现，内容相同 | 恢复原资产 ID 和绑定，新增名称别名，记录改名事件 |
| 多个同内容文件使改名关系不唯一 | 不合并、不猜改名，进入待确认 |
| 原路径内容被替换 | 同一逻辑资产新增内容版本，原绑定仍指旧版本；用户确认前标为已变更 |
| 删除文件 | 标记缺失，保留逻辑身份、旧绑定和历史快照 |
| 同时改名与修改内容 | 无法可靠推断身份，用户手动选择新文件；不静默恢复 |

逻辑 ID、当前路径和内容哈希分离。引用历史包含剧本版本、需求、资产版本、章节/镜头和源行。素材变化提示历史与当前受影响镜头；已从当前剧本删除的镜头仍显示为历史镜头。不会销毁旧结果或自动重生成。

## 保存与身份

影片身份创建一次；章节与镜头 ID 从影片身份和编号稳定派生。改标题、移动位置不会换 ID；改编号作为新增/删除处理，旧关系保留，不猜测重编号迁移。

`project.json` 的版本为 `preparation-0.2`，与旧工程的 `schema_version: 0.2` 无关。内容包括草稿、上次有效解析结果、剧本历史、资产与版本、明确绑定、引用历史、变更事件和界面位置。

共用旧 `write_json` 的临时文件、flush/fsync、原子替换机制；关键提交失败会恢复内存状态。媒体快照先落盘、关系后提交；意外中断最多留下尚未引用的快照，不把半完成关系标为 Ready。

整体复制项目目录即可迁移，生产关系使用相对路径。根目录 `.v02-session.json` 只保存此机器上次打开的项目路径，不属于生产数据。备份应包含项目内 `.history`；不要只复制 `project.json`。

## UI 技术与视觉母版

本轮使用本机已有 PySide6 6.10.2：原生文本编辑、分栏、文件选择、后台线程、图像与媒体预览。Python 核心与界面分离，不引入 Web 服务或前端构建链。

选择它是为了降低新工作区、多媒体和后续时间线交互的实现成本；比继续扩充旧 ttk 组合控件增加了一个运行依赖，但避免保留旧业务绑定。替换成本限于界面层。没有复制 Qt 源码或建设独立组件框架。

官方依据：[Qt for Python](https://doc.qt.io/qtforpython-6/)、[QPlainTextEdit](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QPlainTextEdit.html)。Qt for Python 提供 LGPLv3/GPLv3 和商业许可；当前按安装依赖动态使用，未来分发打包应带齐相应许可与第三方声明。

当前正式视觉基线为 C「镜头上下文」：深蓝黑空间、左侧真实媒体与资产参照、右侧可阅读的 Production Script、底部横向 Shot Index。剧本默认阅读，按“编辑剧本”进入原始可执行文本；准备状态不冒充后续候选红黄绿。详见 [C 母版 Qt 实现与真实窗口](../evidence/V0.2-C-Qt/实现回执.md)。

示例中的人物和红伞是本项目程序绘制的原创 SVG 示意资产；便利店雨夜是 AI 生成的 Demo 环境概念参照。三者均以真实 PNG 文件进入现有资产映射与监看流程，界面明确标出 DEMO。它们不是生成影片质量、真实人物一致性或成片成果证据。
