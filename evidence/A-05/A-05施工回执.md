# A-05 施工回执

## 当前任务

将现有 Tkinter GUI 整理为可实际使用、可现场展示的个人视频生产工具，同时保持 A-01～A-04 生产数据和主链不变。

## 现场起始状态

已恢复三份冻结文档、A-01～A-04 回执、A-04 能力证明、README、当前 GUI、生产数据、测试与证据。无 Git 仓库，未发现 AGENTS.md。施工前 27 项测试通过，114 份文件形成 [基线](baseline.json) 和 before-A05.zip。

旧 GUI 能完成生产闭环，但角色与场景表单层级弱，Shot 列表缺少状态，Review 预览较小，生产上下文与工程 ID / 路径混排。真实 Before 截图来自 A-04，未重绘或伪造。

## UI 技术决策

保留 Tkinter / ttk。现场问题可通过现有控件和布局解决，无需引入前端工程、主题包或新播放器。复用 ttk Treeview、Notebook、Scrollbar、现有 Pillow 与 FFplay，新增运行依赖为 0。

## 信息架构

四个工作区：Characters、Scenes、Shots、Review。资产详情分为 Identity、Look / State、References；Review 下方分为生成上下文、执行摘要、工程详情。没有 Dashboard、营销页或 Agent 控制台。

主要 UI 文件为 `app/gui.py`、`app/scene_gui.py`、`app/review_gui.py`；新增 `app/workspace_ui.py` 组织布局、`app/ui_widgets.py` 复用轻量控件、`app/ui_presenters.py` 从已有记录派生展示状态。

## Character / Scene

资产列表显示缩略图、名称、示例标记、Look / State 数量与参考图数量。详情顶部显示封面、稳定身份摘要和变体名称。Character 与 Scene 视觉一致，语义仍明确分开。

Reference 列表显示缩略图和身份 / 稳定 / Look / State 用途，右侧预览不再挤占列表高度。导入、移除关联及变体绑定继续调用原业务方法；缺图有明确提示。

## Shot

列表显示镜头描述、角色、场景、短 ID、状态和 Take 数量。详情分为“谁”“在哪里”“做什么 / 怎么拍”和生成方式。长描述支持多行编辑、独立滚动；保存与生成按钮固定在底部。

状态直接从原 Execution / Review 派生为待补场景、可生成、生成中、待审核、可重试、执行失败、已选定，没有新增持久化状态机。

## Review

左侧为 Take 导航，中间以媒体预览为视觉中心，右侧为 Human Gate。SELECTED、REJECTED、待审核使用明确标签与克制底色；最终素材同时显示在导航上方。

Select 与 Reject 分区，重复选择按钮禁用。Reject 保存原因，Retry 可调整描述并创建新 Task / Take；有进行中任务时禁用 Retry。决策区可滚动，Retry 固定在底部。每次操作提供反馈，历史素材不被覆盖。

## Production Context

默认显示当次 Character / Look、Scene / State、有效参考图及最终生成描述。工程详情保留 Task、Execution、Shot ID、Model、Retry 来源、Request、素材路径、哈希与 Trace 路径。大段 base64 在控件中摘要显示，完整请求文件仍保留。

历史上下文从保存的 Task 读取，不随当前资产编辑变化。

## Provider / Harness

界面明确显示 MOCK 或 ZERO-CALL，并说明 Fixture 未真实调用视频 API；REAL 标为未启用。当前视频仍是测试占位素材。

执行摘要按 Execution、Task、Shot 三个 ID 匹配 A-04 旁路 trace，显示读取 Shot、构建任务、Kling O3 Dry Run / 入库、ffprobe、回读等已记录步骤。明确标注历史执行，不表示 DSH 当前运行。缺失或损坏 trace 不阻塞生产数据读取；不展示思维过程。

## 本轮关键视觉变化

统一字体层级、留白和低饱和配色；资产有封面和摘要；Shot 可扫描；Review 媒体优先；人工决定与模拟模式清楚可见。状态栏限制过长错误摘要，避免挤压工作区。

## 遗留 / 风险

继续按单写入者使用同一 data，GUI 与 DSH 不应同时编辑。视频播放依赖本机 FFplay，使用外部窗口。当前最小窗口与 Windows DPI 验证范围见上文。Harness 摘要为可选旁路证据，迁移数据但不复制 evidence 时会显示“无匹配记录”，不影响生产数据。

真实角色一致性、场景一致性和 Provider 成片质量仍未验证，UI 整理不改变这一事实。

## 当前真实能力

用户可以通过统一的本地工作台浏览和编辑角色、场景、Reference 与变体，扫描 Shot 的双资产关系和生产状态，执行零调用视频生成，查看多 Take、播放、Reject、Retry 并明确选择最终素材。生成上下文可追溯，工程证据需要时可展开；示例与模拟边界清楚，适合现场解释完整生产链。
