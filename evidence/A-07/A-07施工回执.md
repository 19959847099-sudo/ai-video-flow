## Voice Asset

独立 Voice ID、名称、稳定描述、语言、默认 Delivery、备注及音频 Reference。Character 通过 character_voices 侧文件关联默认声音。Provider Voice ID 放在独立 voice_mappings，不污染 Voice 身份。GUI 导入参考音频后按哈希保存到相对路径，重启可读；参考音频不上传、不自动克隆。

## Dialogue

Dialogue 用稳定 ID 引用 Character 与 Shot，保存顺序、文本和 Delivery。同一 Shot 创建两句示例对白，顺序 1 / 2；不复制整套资产。重复顺序、跨角色归属等无效关系会阻止保存。

## TTS Provider 选型

选择 MiniMax speech-2.6-hd，中文对白、系统声音与 whisper 等 Delivery 官方契约适配简单。只记录 ElevenLabs 为备选，未扩张接入。依据及版本选择见 [官方契约审查](contract-and-architecture.md)。该选择不包含音质比较结论。

## Audio Generation Task

中立 AudioTask 固定 Dialogue / Character / Shot / Voice 快照、当次文本、Delivery、语速与通用音频参数。MiniMax ID 仅在外围 Request Mapping。Task 与 Request 均有 SHA-256 校验；Retry 创建新 Task，不覆盖历史。选中结果可以恢复原 Dialogue 和当次修改后的提交文本。

## Real TTS Adapter

依据官方同步 t2a_v2 接口实现 Request / Response Mapping，校验 HTTP 状态、业务状态、trace_id、hex 和 WAV。同步 API 不虚构远端异步 task ID；本地 Job 管理 pending / processing / completed / failed。请求可在 GUI 工程记录与 JSON 审查。真实 HTTP Transport 未启用，不需要 Key。

## Zero-call / Fixture

唯一执行 Transport 生成本地 PCM WAV 并返回官方形状响应；不存在自动转真实调用的后备路径。GUI 验收期间 socket 被阻断，连接尝试为 0。所有合成音频和字幕均标记 Fixture。WAV 是测试音调，不是合成对白。

## Audio Result

真实文件按结果 ID 落盘，Result 关联 AudioTask / Dialogue / Character / Shot / Voice，并记录媒体哈希与 ffprobe 信息。本轮三个结果均为 4 秒、32000 Hz、单声道 PCM WAV。GUI 实际启动 FFplay，已截取播放器窗口。

## WhisperX / Alignment

**本轮为 Contract / Fixture，未真实运行 WhisperX 模型。** 当前 Python / PATH 无已配置的 WhisperX 执行能力，未安装模型。薄外部 worker 契约消费实际 AudioResult 路径和哈希，解析官方 segments / words 形状。Fixture Transcript 独立于 Expected Dialogue，词时间不包含伪造 confidence。不能据此证明真实识别或对齐准确率。

## Subtitle

三个实际 UTF-8 SRT 文件，时间位于对应 WAV 时长内，文本带 [FIXTURE]。Alignment 保存 AudioResult / Task / Dialogue / Shot 来源与媒体、字幕哈希；重启可读。可从保存的 Alignment 重新生成 SRT，无需重新调用模型。Shot Handoff 明确包含选中的 Audio、Task、Voice、Alignment 和字幕路径。

## DSH

复用官方 DeepSeek Harness 0.1.5-rc.2，新增 prepare_dialogue_audio 工具。真实 CLI 执行：中立任务 → TTS Fixture → WAV 回收 → Alignment Fixture → SRT；证据见 dsh-run/trace.json。工具返回 human_review_required，执行前后检查默认 Voice 和 AudioReview 未改变。没有暴露 Select 工具，未做 LLM 自主规划。DSH 退出后 GUI 独立读取和审核全部数据。
