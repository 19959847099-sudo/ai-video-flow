## Timeline / Rough Cut 数据结构

TimelineDefinition 保存独立 ID、名称、显式 Shot ID 数组、允许缺失音频 / 字幕选项和固定 V0 策略。Builder 只读生产事实，生成独立 Manifest、OTIO、Preview Plan 和 Sidecar SRT。构建使用新 ID，rough_cut_current 明确指向当前构建；不把 OTIO 当生产数据库。

主要模块：app/rough_cut.py、app/rough_cut_gui.py；数据目录：timelines、rough_cut_builds、rough_cut_current、handoffs。原 Character / Scene / Shot / Voice / Dialogue / Result 模型与文件保持。

## Timeline Validation

验证顺序唯一、Shot 存在、Selected 状态和归属、拒绝状态、媒体文件、SHA-256、ffprobe stream / codec / duration / rate / timebase、音频来源、Alignment / Subtitle provenance 与哈希。错挂字幕或损坏媒体 Block；未选择视频从不使用候选顶替。

默认不允许无音频或缺失字幕。人工开启后保留 Warning。Selection、顺序或来源变化后，旧构建为 STALE，必须重新 Build。Manifest 自身被修改也阻止使用。Ready / Blocked 与尚无构建的 Draft 清楚区分，不评价审美。

## Duration / FPS / Timebase

实际探测素材，不信任 JSON 手写 duration。Timeline rate 取人工顺序中首个视频的 avg_frame_rate，以 Fraction 保存；实际示例为 24 fps。每个视频采用完整帧范围，source in=0，out 为视频实际时长向下量化，timeline in/out 为统一帧计数。

混合帧率保留原始规格并 Warning，Preview 统一重采样。新增测试真实生成一个 30 fps 源，与 24 fps 源组合后输出 24 fps；故意把 result.duration 改为 999 仍按 ffprobe 得到正确 6 秒。

## Video / Audio Duration Mismatch

固定 **video-driven trim**：每 Shot 由视频决定时长，对白依序排列，超出部分截短并报告；不足部分静音，不延长画面或自动改节奏。实际 3 秒视频配 4 秒 Selected Audio，明确记录 4 → 3 秒裁切。字幕第二句从 2.1～3.7 秒裁为 2.1～3.0 秒。

## OpenTimelineIO

真实运行 **0.18.1**。标准 Timeline / Stack / Video Track / Audio Track；视频和音频为 Clip + ExternalReference，无音频区间用 Gap。RationalTime / TimeRange 表达时间；metadata 保留 Shot / Result / Task / Dialogue / SHA 与源媒体规格。仅使用官方原生 otio_json Adapter，不自研 OTIO Serializer。

## OTIO Output

实际 timeline.otio 已生成、重新读取，并通过 is_equivalent_to round-trip 验证。当前 DSH 构建为 **8537794881984f73ac7b075b87b3db15**：2 个 Video Clip、1 个 Audio Clip、总长 6 秒，顺序和媒体引用正确。otio-inspection.json 保存版本、数量、顺序和时长。

## Rough Cut Preview

FFmpeg 按明确顺序处理源视频，统一画幅 / FPS、截取音频、补静音并拼接；使用成熟编码器，不自研媒体处理。实际输出 **6.000 秒、640×360、24 fps、H.264、单声道 48 kHz AAC**。

除 ffprobe 外，还解码每个 Shot 的实际画面与对应 Selected 源对比，平均像素差约 0.042 / 0.043，确认装配顺序。GUI 已真实启动 FFplay；完全重启后再次播放成功。界面、Manifest 和包说明均标记 ROUGH CUT / FIXTURE SOURCE MEDIA / NOT FINAL MASTER。

## Audio Policy

Preview 静音所有视频原音，只使用 Selected Dialogue；缺失且人工允许的部分补静音。实际解码音频：对白区间 RMS 约 0.0848，静音区间 RMS=0，符合前 3 秒对白、后 3 秒静音。不是声音质量评价。NLE 导入时仍要求人工核对视频内嵌原音静音设置。

## Subtitle Handoff

Sidecar UTF-8 SRT，不烧录、不引入字体依赖。使用选中音频自己的 Alignment，偏移到全局时间并按相同采用区间裁切；每句保留 [FIXTURE]。包内同时保存合并 SRT 和使用到的源 SRT，Manifest 记录 Alignment / Audio IDs 和哈希。模拟转写不能证明语音识别准确率。

## NLE Handoff

目标 **DaVinci Resolve**，实际交付原生 `.otio` + 相对媒体 + 合并 SRT + Preview + Manifest + 导入说明。官方文档已确认 OTIO 路径，依据与边界见 [Timeline 架构](timeline-architecture.md)。不额外生成 FCP XML / EDL，不深入第二个 NLE。

已验证 OTIO 文件与媒体、时间、metadata、包内路径及复制恢复。**未进行 Resolve GUI 人工导入**，不保证自定义 metadata、音轨路由或字幕样式在 NLE 内无损保留。使用者需导入、必要时 relink、静音视频原音、从 00:00:00 单独导入 SRT 并复核后人工精剪。

## Portable Handoff

Working Timeline 引用既有媒体，不复制全部生产目录。只有人点 Export Handoff 才创建独立 handoffs/<id>，按 SHA 去重复制实际用到的媒体，不带失败候选。

实际目录包含 timeline.otio、manifest.json、rough-cut.mp4、subtitles.srt、otio-inspection.json、media/、README.txt。全部播放所需引用是包内相对路径。复制到另一临时目录后重新读取 OTIO、核对媒体哈希、解析 Preview 和字幕来源均通过。production_path 仅作历史回查，不是包恢复所需的唯一地址。

## DSH

官方 DeepSeek Harness 实际执行新增 **prepare_rough_cut(timeline_id)**：读取保存的人工顺序和策略 → 校验 Selected 媒体 → Manifest → OTIO → FFmpeg Preview → 返回 human_review_required=true。

执行前后检查 Timeline / 视频 Review / 音频 Review 文件不变。不会自动 Select、修改顺序、删除 Shot 或导出便携包。DSH 退出后，GUI 独立打开其构建、播放、再由人工 Export，验证生产事实和交付文件不依赖 DSH 进程。
