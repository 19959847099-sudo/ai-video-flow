# V0.2 Production / Candidate / Review 施工回执

基线 `bc13613`。本轮按 C「镜头上下文」视觉语言接入真实生产审核路径：当前 Shot 的 Missing Requirement → 本地图像 Fixture 或导入 → 自动归档与命名 → Candidate → Green / Yellow / Red → 明确选用 Current → Preparation Resolved。

- **KEEP**：V0.2 Parser、Requirement、素材扫描 / 校验、资产版本与 Preparation 布局。
- **ADAPT**：现有绑定记录增加可追溯的 Candidate 身份；素材扫描同步 Candidate 当前路径，改名不换 ID，内容变化使绑定进入 Changed。
- **不纳入新主链**：旧 A-02 `selected_result_id` 把审核与选用耦合；旧代码仍作为历史技术底座，本轮 V0.2 路径不依赖它。

`project.json` 加入可恢复的 Job、Candidate 与解除绑定记录。Candidate 的 ID、需求 / 项目 / 章节 / 镜头、媒体类型、Take 序号、文件路径、内容哈希、创建时间、来源、可选 Provider / Job / 生成元数据、审核、备注和历史分开保存。文件按 `library/<kind>/take_<序号>_<ID>.<扩展名>` 自动落盘；文件名不承担逻辑身份。绑定变更同时记录前一 Current 和受影响镜头。Red 保留并沉到 Take 列表末尾；多个 Green 可共存；未审核或 Yellow 不会自动进入正常生产。

图像 Fixture 在本地生成明确写有 “NOT AI GENERATED” 的示意媒体，零 API 调用；音频、视频通过导入验证同一 Candidate / Review / Binding 模型。截图中的主图片来自现有 Demo 环境参照的真实文件，项目明确标记 DEMO，并非生成成片。
