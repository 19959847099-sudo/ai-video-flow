# V0.2 章节准备工作区 · 视觉方向重构

本轮目标是将已经通过的准备闭环呈现为现代、专业、克制的 AI 影视生产工具。施工只触及 Qt 呈现层、视觉说明与代表性 GUI 文案断言；Parser、资产映射、文件同步、生产状态语义保持原样。

## 母版方向

实际工作区采用固定三域：左侧 Project Bin / 章节镜头目录，中间 Script / 可执行剧本，右侧 Source Viewer + References / 媒体监看与资产列表。顶部为紧凑工具栏，章节完成度变成信息带，底部保留操作反馈。

剧本区使用浅冷灰底和蓝灰色语法层级，保证长时间读写；其他工作区以深灰中性色区分面板。强调蓝仅用于当前选择、关键操作和媒体焦点。状态以“就绪、缺失、待确认、已变更”文字和小色点共同表达。控件保持小圆角或直角、细边界和紧凑行高。

真实入库图片在 Source Viewer 按原比例监看，条带显示媒体名称、实际像素尺寸与文件格式。资产行显示缩略图、类型、引用镜头数、状态和源行。点击图片或名称切换监看，预览打开现有真实媒体窗口。音视频参照不伪造缩略图或波形，点击后打开原有播放预览。对缺失文件显示同步提示。

这是视觉与操作层的调整；没有引入虚构时间线、播放器进度或后台制作状态。示例的店面、人物与雨伞仍是明确标注的原创矢量示意资产，不是生成质量证据。

## 参考与取舍

- [DaVinci Resolve Media 官方说明](https://www.blackmagicdesign.com/products/davinciresolve/media)：媒体池与源媒体检视的职责分离。这里借鉴“素材与监看并置”的工作方式，不复制其素材组织或界面资产。
- [Nuke Studio 官方界面说明](https://learn.foundry.com/nuke/12.1/content/getting_started/using_interface/nuke_studio_environments.html)：固定 Viewer 与 Properties 的工作区关系。这里借鉴明确面板边界，没有加入节点或专业合成功能。

上述视觉选择是对官方工作区资料的设计推断，不声称与任一产品具有相同功能。

## 验证与边界

- 本轮修改后，代表性的五项 Qt GUI 测试通过：导入剧本与三类参照直至 Ready、歧义/版本选择、无效草稿定位与恢复、项目位置恢复、紧凑主操作。
- 实际生成标准、紧凑、资产和映射四张窗口截图，并逐张检查监看区、剧本可读性、状态、按钮及滚动。
- 未修改且未重复运行 Parser、资产映射和旧 FFmpeg/OTIO 的大套验证；`semantic-baseline.json` 记录正式语义文件的施工前哈希，收口时再次核对。
- 这轮提高了准备工作区的制作工具气质；后续图片、音声、镜头、审核和轻剪页面仍须沿同一视觉语言施工。最终视觉方向由用户验收。
