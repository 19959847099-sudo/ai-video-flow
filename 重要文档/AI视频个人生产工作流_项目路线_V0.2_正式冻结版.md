# AI 视频个人生产工作流｜项目路线 V0.2 正式冻结版

**版本：V0.2**  
**冻结日期：2026-09-17**  
**状态：正式冻结**  
**上位依据：`项目定义 V0.2`**  
**历史关系：本版本正式取代《项目路线 V0.1》。V0.1 可本地留档，但不再作为当前施工路线。**  
**本文件负责：规定 V0.2 应如何从旧工程底座迁移到新的剧本驱动生产主链，以及各阶段什么结果才算完成。**

---

## 1. 路线总原则

V0.2 不再以“继续堆更多能力模块”为路线核心。

本轮路线只围绕一个目标：

> **把已经明确的产品定义真正施工成一条低摩擦、可长期重复使用的 AI 视频个人生产工作流。**

路线按照生产能力推进，而不是按照数据库、API、前端、后端等技术模块推进。

---

## 2. 新主链

V0.2 的唯一主链为：

```text
规范剧本
↓
剧本解析
↓
资产需求扫描
↓
检查素材库
↓
缺失图片 / 音声 / 视频参照资产
↓
生成 / 导入 / 确认 / 入库
↓
章节 Ready
↓
逐镜生产
↓
批量候选
↓
红 / 黄 / 绿审核
↓
绿色素材进入轻剪辑
↓
整集观看
↓
局部返工
↓
重新收敛
↓
输出
```

任何新功能都必须能说明：

> **它具体改善主链中的哪一个真实摩擦。**

不能回答，就默认不进入施工。

---

## 3. 对旧工程的处理原则

此前 A-01 ～ A-08、UI-Final 以及已有代码全部视为技术底座。

### 3.1 可直接复用

已有能力若与新主链一致，可直接复用，例如：

- Provider Adapter；
- 文件落盘；
- 媒体探测；
- FFmpeg / ffprobe；
- 音频 / 视频播放；
- Review 状态；
- Retry / Select；
- OpenTimelineIO；
- Rough Cut / Handoff；
- 现有测试工具；
- 已稳定的基础媒体组件。

### 3.2 可改造

已有 Asset、Shot、Review、Timeline、GUI 等结构，如果稍作调整即可服务新主链，则直接改造。

### 3.3 可删除

若旧结构：

- 与新剧本驱动模型冲突；
- 让新 UI 被迫迁就旧架构；
- 增加不必要状态；
- 只为旧 Demo 存在；

则允许删除。

### 3.4 不承担不必要兼容

V0.2 不要求旧数据结构、旧 UI、旧命名方式永久兼容。

历史工程是：

> **可复用资产，不是新产品的约束。**

---

## 4. 验证原则

### 4.1 不过度验证

已经可靠证明的基础能力不重复证明。

例如：

- FFmpeg 能拼接；
- ffprobe 能读取媒体；
- OTIO 能生成时间线；
- WAV / MP4 能播放；
- 已有 Fixture 能产生有效文件。

除非这些能力本轮被修改，否则不重复做大规模回归。

### 4.2 重点验证新主链

重点验证：

```text
剧本能否正确解析
↓
能否推导正确资产需求
↓
缺失资产能否进入生成 / 导入
↓
资产能否正确入库与再次调用
↓
镜头能否正确装配参照条件
↓
候选能否审核
↓
绿色素材能否进入轻剪
↓
返工能否回到正确层级
↓
一章能否完整跑通
```

### 4.3 验证以变化范围为准

```text
改了哪里
↓
验证哪里
```

不得为了“看起来严谨”重复证明未变化能力。

---

## 5. UI 路线：视觉质量是一等目标

V0.2 不允许“先把功能堆完，最后再美化”。

### 5.1 UI 质量门槛

每一个核心工作区必须同时达到：

- 功能可用；
- 信息层级清楚；
- 视觉统一；
- 现代；
- 有创作工具气质；
- 可直接截图进入作品集。

### 5.2 先定视觉方向，再铺页面

推荐顺序：

```text
寻找 / 生成视觉参考
↓
确定设计语言
↓
先完成一个核心页面
↓
视觉达到满意线
↓
复用到整个系统
```

### 5.3 实现方法不冻结

允许：

- 复用成熟组件库；
- 参考现成优秀产品；
- 自建组件；
- Codex 自行绘制 SVG / CSS 视觉；
- Codex 调用图像生成能力制作 UI / Demo 素材；
- 混合多种方案。

只看最终效果与维护成本。

### 5.4 不做假赛博

默认视觉方向应偏：

> **克制、现代、专业、创作工具感。**

不强制黑色，不强制霓虹，不为了“AI 感”堆装饰。

### 目标

让工程正式从旧 V0.1 主线切换到 V0.2。

### 必须完成

2. 识别旧工程中：保留 / 改造 / 删除的模块；
3. 不做大规模代码迁移，只形成明确处理表；
4. 选定 UI 视觉方向与核心参考；
5. 明确一个核心页面作为视觉母版。

### Done

## 7. 阶段 1：剧本语言与解析主链

### 目标

让系统能够把 V0.2 规范剧本稳定解析成生产需求。

### 核心能力

至少支持：

- 影片；
- 章节；
- 镜头；
- 多人物角色行；
- 人物 / 年龄 / 服装 / 音声；
- `-` 空位；
- `【】` 完整资产引用；
- 环境 / 背景音；
- 关键物件引用；
- 自然语言镜头描述；
- 镜头视频参照；
- 表演 / 对白 / 连续性 / 备注。

### 关键要求

Parser 只结构化真正需要结构化的内容。

不得把自然语言创作区拆成大量强制字段。

### Done

给定一份规范剧本，系统能够输出：

```text
章节
镜头
角色状态
环境
背景音
关键物件
完整视觉资产引用
Voice 需求
视频参照需求
自然语言生产描述
```

且无歧义。

---

## 8. 阶段 2：资产需求扫描与素材库同步

### 目标

让系统从剧本自动回答：

> **现在生产这部片，还缺什么？**

### 核心能力

系统扫描并区分：

- 已存在；
- 缺失；
- unresolved；
- 已变更可能影响历史镜头。

### 资产类型

至少覆盖：

- 人物视觉；
- 年龄 / 服装视觉；
- 完整角色视觉；
- 环境 / 完整背景；
- 关键物件；
- Voice / 音声状态；
- 镜头视频参照。

### 文件系统开放

支持：

- 系统内自动入库；
- 用户直接向文件夹加入素材；
- 用户替换素材；
- 用户重命名；
- 重新扫描同步。

### 资产变更影响提示

资产发生变化后：

- 标记受影响镜头；
- 不自动删除历史结果；
- 不自动重生成；
- 用户决定下一步。

### Done

给定一份剧本与一个素材库，系统能明确展示：

```text
已有资产
缺失资产
引用关系
受影响镜头
```

用户不需要手工建立资产清单。

---

## 9. 阶段 3：图片 / 音频资产生产

### 目标

把“缺失资产补齐”从文件管理问题变成连续生产操作。

### 图片生产

允许生成：

- 人物；
- 年龄 / 服装状态；
- 完整人物组合；
- 背景；
- 关键物件；
- 其他需要的视觉参照。

### 音声生产

允许：

- 创建 / 绑定 Voice；
- 参考音频；
- Voice ID；
- 对白音声；
- 外部音声导入。

### 统一生产心智

```text
缺失
↓
生成 / 导入
↓
看 / 听
↓
红 / 黄 / 绿
↓
确认可用
↓
自动入库
```

### Done

用户从“缺失资产”界面出发，可以不手工命名文件地完成至少：

- 一个图片资产；
- 一个音声资产；

并再次被后续镜头自动调用。

---

## 10. 阶段 4：统一 Media Job / Batch / Save 层

### 目标

让图片、音频、视频三类 Provider 不再各自拥有完全不同的任务管理逻辑。

### 建议统一的能力

```text
Create Job
↓
Queue / Submit
↓
Pending / Processing
↓
Completed / Failed
↓
Download
↓
Local Save
↓
Bind to Asset / Shot
↓
Review
```

### 批量要求

用户可以指定多个候选。

Provider：

- 原生支持 batch → 使用原生 batch；
- 不支持 batch → 系统拆分多个 Job。

用户不需要关心差异。

### 开源复用

本阶段优先审计成熟开源实现，重点复用：

- Provider Adapter；
- Job Queue；
- Retry；
- 下载；
- 批量保存；
- 状态轮询。

不要求一个项目包办 Image + Audio + Video 三类全部能力。

### Done

至少三类媒体任务在上层表现出一致的任务心智，并能自动保存和绑定。

---

## 11. 阶段 5：正式镜头生产

### 目标

让用户进入真正的：

> **抽卡 → 看 / 听 → 判断 → 再抽 / 下一镜。**

### 镜头任务装配

系统从剧本与资产库自动装配：

- 人物；
- 年龄；
- 服装；
- Voice；
- 环境；
- 关键物件；
- 镜头视频参照；
- 自然语言动作；
- 表演；
- 对白；
- 连续性；
- 当前镜头要求。

### 音声路线

允许：

1. 视频原生音声；
2. 独立 Audio API；
3. 外部音频导入；
4. 音声先行作为视频条件；
5. 无角色音声。

### Done

一个真实镜头能够完成：

```text
自动装配参照
↓
批量生成候选
↓
查看 / 试听
↓
红黄绿
↓
继续抽 / 结束该镜头
```

---

## 12. 阶段 6：统一红黄绿审核

### 目标

让图片、音频、视频共享同一种候选审核心智。

### 状态

```text
Green  = 可用
Yellow = 待定
Red    = 废弃
```

### 规则

- Green 可进入正常生产素材池；
- Yellow 保存，但默认不进入轻剪素材池；
- Red 保存历史，但默认不进入正常生产；
- 一个镜头可以有多个 Green；
- Green 不等于最终永久选中。

### Done

用户高频生成时，可以只进行最少点击完成候选分类，不需要每次立刻作最终决策。

---

## 13. 阶段 7：轻剪辑与生产往返

### 目标

让“生产”和“剪辑”不再是两个完全断开的世界。

### 推荐布局

```text
左：素材
中：Preview
右：工具
下：Timeline
```

### 核心功能

优先实现：

- 拖入；
- 排序；
- 替换；
- 裁头尾；
- 分割；
- 删除；
- 吸附；
- 播放头；
- Undo / Redo；
- 基础音量 / 静音；
- 字幕。

### 返工往返

时间线发现问题后，可以：

- 直接换另一个 Green；
- 跳回对应 Shot 再抽；
- 修改剧本；
- 修改资产；
- 新结果自动回到素材池。

### 不做

本阶段明确不做：

- 专业调色；
- 复杂蒙版；
- 跟踪；
- Fusion 级合成；
- 专业混音；
- 大型插件生态；
- 完整专业 NLE。

### Done

能够在同一生产环境内完成：

```text
绿片成集
↓
播放
↓
发现问题
↓
局部返工
↓
替换回时间线
↓
继续观看
```

---

## 14. 阶段 8：章节级收敛与输出

### 目标

让用户以章节为单位真正结束生产。

### 输出方向

允许：

- 快速预览；
- 直接成片；
- 专业剪辑交付包；
- 绿色素材；
- 音频；
- 字幕；
- 批量多集输出。

### 专业软件边界

当任务进入：

- 精细调色；
- 高级合成；
- 专业混音；
- 复杂字幕动画；
- 专业最终剪辑；

则交给 Resolve / Premiere / CapCut 等成熟工具。

### Done

至少一章能够从规范剧本完整跑到可播放结果，并可继续交给专业 NLE。

---

## 15. 阶段 9：真实生产与作品集证据

### 目标

用真实生产检验工作流，而不是继续凭想象扩功能。

### 真实生产重点观察

- Human Time / Finished Minute；
- 资产准备时间；
- 找文件时间；
- 重复上传次数；
- 候选整理时间；
- Attempts / Accepted Shot；
- Retry Rate；
- 返工定位成本；
- 从打开项目到恢复状态所需时间。

### 真实模型验证边界

如果当前不授权付费调用：

- 允许 Fixture；
- 允许 Zero-call；
- 允许 Contract 验证；

但不得声称：

- 真实生成质量已验证；
- Voice 一致性已验证；
- 视频模型一致性已验证；
- 实际成本已验证。

当预算与授权存在后，再进行受控真实生成。

### Done

完成至少一轮真实内容生产，并能够明确说明：

> **V0.2 相比手工生产到底少了哪些混乱与重复操作。**

- 音声资产生产；

## 17. API 路线

### 17.1 三类能力

```text
Image Provider
Audio Provider
Video Provider
```

### 17.2 Adapter 原则

- 只接真实会用的 Provider；
- 核心数据不绑定 Provider；
- Adapter 保持薄；
- Provider 变化不迫使核心剧本与资产语义迁移；
- 不为了“全平台支持”建设庞大网关。

### 17.3 开源优先审计

优先寻找成熟实现解决：

- Provider 抽象；
- Queue；
- Batch；
- Retry；
- Polling；
- Download；
- Local Save。

产品层的剧本、资产、审核和返工语义由本项目自己掌握。

---

## 18. 文件与数据路线

### 18.1 用户层

用户应能够：

- 不碰文件系统完成大多数工作；
- 需要时直接打开文件夹；
- 自己添加 / 替换 / 重命名素材。

### 18.2 系统层

系统负责：

- 自动命名；
- 自动保存；
- 资产映射；
- 状态记录；
- 关系恢复。

### 18.3 内部数据

允许使用：

- Markdown；
- JSON；
- YAML；
- 文件系统；
- SQLite；
- 其他轻量方式。

具体实现按真实查询与状态需求决定。

不因为“架构高级”引入大型数据库、微服务或复杂基础设施。

---

## 19. 视觉素材路线

Codex / AI 执行者可自行决定 UI / Demo 视觉素材的生成方式。

允许：

- 图像生成；
- SVG；
- CSS；
- 程序化图形；
- 开源图标；
- 已有素材处理；
- 多种方式混合。

要求：

1. 最终视觉好看；
2. 不制造版权 / 来源风险；
3. 不伪造生产事实；
4. 不为了做素材而扩张成独立设计系统。

- `/`；
- `-`；
- `【】`；
- 人物 / 年龄 / 服装 / 音声；
- 环境 / 背景音；
- 关键物件；
- 镜头参照；

## 21. 开源路线

开源不进入当前强制施工范围。

当满足以下条件后再考虑：

1. V0.2 已真实生产多轮；
2. 剧本与资产规则稳定；
3. Provider 接口边界稳定；
4. 工作流确实减少大量摩擦；
5. 已有清晰使用说明。

届时可以将：

- 核心工作流；
- 剧本规范；
- Provider Adapter 接口；
- 资产扫描；
- 红黄绿审核；

作为开源核心，不要求把所有 Provider 都由作者本人维护。

## 22. 施工方法

每一轮施工仍按：

```text
明确本轮用户价值
↓
确定 Scope / Done
↓
先审计旧代码与成熟开源能力
↓
Reuse / Modify / Delete / Build
↓
大轮施工
↓
只验证变化与主链
↓
验收
↓
继续下一段主链
```

默认倾向：

> **大轮施工，快速闭环，有问题再调整。**

不为了“安全感”机械切碎。

---

## 23. 阶段升级原则

阶段推进不以代码量和日期为依据。

满足：

> **当前能力真实存在，主链稳定，UI 达到当前阶段质量线。**

即可收口。

不因为“再想一点也许更完善”无限延长设计阶段。

---

## 24. 路线调整原则

允许因为以下事实调整实现：

1. 真实生产发现更大摩擦；
2. 新 Provider / API 改变最佳方案；
3. 成熟开源项目显著降低维护成本；
4. 旧工程结构成为新主链阻碍；
5. 当前 UI 方案达不到视觉质量；
6. 真实生产证明某条规则不适用。

不得仅因为：

> “新技术看起来更酷”

而改变路线。

---

## 25. V0.2 最终路线摘要

```text
0  基线切换 + UI 视觉方向
↓
1  剧本语言与 Parser
↓
2  资产扫描 + 文件同步
↓
3  图片 / 音声资产生产
↓
4  统一 Media Job / Batch / Save
↓
5  正式镜头生产
↓
6  红黄绿审核
↓
7  轻剪辑 + 生产往返
↓
8  章节级输出
↓
9  真实生产验证 + 作品集证据
```

每一步始终遵循：

> **新主链 > 旧架构**  
> **真实价值 > 功能数量**  
> **复用 > 重写，但不迁就旧代码**  
> **验证变化 > 重复验证**  
> **好看且好用 > 仅仅能用**  
> **有限规则 > 无限兼容**  
> **用户判断 > 自动审美替代**

---

## 26. 路线成功标准

V0.2 路线成功不是“又接了更多模型”。

而是最终形成：

> **一条以规范剧本为源头，能够自动发现和补齐一致性资产，统一管理图片 / 音频 / 视频生成，支持批量候选与红黄绿审核，并能在轻剪辑中快速返工、持续完成多章节 AI 视频生产的高完成度个人工作流。**

同时，它必须让用户真实感受到：

> **生成本身之外的大量混乱时间，被系统压缩掉了。**
